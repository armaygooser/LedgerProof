# 演示事实边界

## 已真实运行和验证

- LedgerProof API 与 CyberGuard 派生容器之间存在真实 HTTP 调用。
- 提案记录、批准记录、核心执行记录、金融执行回执、独立复核记录、核心回滚记录和金融释放回执真实写入持久化审计账本。
- 每条审计记录包含当前记录 SHA-256、前序记录 SHA-256 和 HMAC；`/audit/verify` 会重新计算整条链。
- 人工批准绑定具体提案哈希，并带 15 分钟有效期。
- 执行动作只覆盖提案中的三笔交易与 ¥294,000 金额。
- 独立复核重新读取付款状态，不直接复用执行函数返回值。
- 回滚追加新记录、保留历史，并使旧复核结论失效。
- Docker Compose 中三个服务通过健康检查和内部网络联通。

## 当前为确定性演示

- 1,024 笔交易、发票、采购订单、供应商信息和审批日志由固定种子生成。
- 七个 Agent 当前是可复现的领域函数，没有调用在线大模型。
- 关系图和控制规则为演示案件预设。
- 付款执行器写入隔离的 JSON 状态文件，没有调用银行、ERP 或真实支付网关。
- 人名、公司名和案件均为虚构。
- 默认密钥是本地演示值。

## 页面用词

可以说：

- “CyberGuard 治理容器正在运行并校验这条决策链。”
- “七个权限隔离角色完成了一次可复现的金融审计流程。”
- “人类批准只对当前提案哈希有效。”
- “回滚保留历史记录，并使旧复核结论失效。”

在接入真实系统之前，不应说：

- 已连接真实银行或企业 ERP；
- 已由在线大模型自主完成调查；
- 已达到生产环境金融合规认证；
- 当前模拟止付等同于真实资金冻结。

## 从演示到真实试点

1. 接入 ERP、发票和供应商主数据的只读连接器。
2. 把规则和模型版本写入每次 Agent 输出。
3. 将确定性 Agent 替换为受工具权限约束的 AgentTeams Worker。
4. 用支付网关沙箱实现 `hold_payment_batch` 和 `release_payment_batch`。
5. 使用企业身份、双人审批、密钥管理和不可变审计存储。
6. 增加财务控制人员签署的测试样本与回归评估。
