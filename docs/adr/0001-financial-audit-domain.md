# ADR 0001：金融付款审计作为 CyberGuard 治理底座的迁移领域

- 状态：已接受
- 日期：2026-09-20

## 背景

CyberGuard Executor 的治理能力（提案绑定审批、有效期、HMAC 审计链、动作历史、独立复核、回滚）最初面向网络安全响应动作。为验证"可信决策基座"可以脱离原始领域复用，需要选择一个新领域：证据必须可追溯、高风险动作必须人工批准、执行范围严格受限、结果需要独立复核、错误动作可以回滚。

## 决策

选择金融付款审计作为迁移领域，并按以下边界实现演示：

1. **演示案件规模**：固定种子生成 1,024 笔交易，定位三笔各 ¥98,000 的阈值拆分付款（合计 ¥294,000），止付范围仅限这三笔，体现最小影响原则。
2. **七 Agent 权限隔离**：证据保全、账目勾稽、异常检测、关系穿透、内控合规、处置规划、独立复核各自持有独立权限边界；处置规划 Agent 只能提案，任何 Agent 都不持有审批凭据。
3. **动作语义通过适配层新增**：不把 CyberGuard 的 `block_ioc` 等安全动作改名伪装成金融动作，而是在 `adapter/finance_adapter.py` 中新增 `hold_payment_batch` 白名单动作，把治理协议映射到金融领域状态（HELD / RELEASED）与回执。
4. **运行时复用而非代码复制**：治理容器直接派生自 `ghcr.io/elsechord/cyberguard-executor:sha-3b34e4c`（源码提交 `3b34e4c`），LedgerProof API 只通过 HTTP 使用治理能力，不在自身进程内重建一套审计链。
5. **两层哈希**：业务证据层为每组输入生成 SHA-256 并聚合为 `evidence_root_sha256`；治理审计层由 CyberGuard 对提案、批准、执行、复核、回滚逐条计算记录哈希、前序哈希与 HMAC。
6. **回滚不删历史**：回滚追加释放回执并使旧复核结论显式失效；再次动作必须重新提案、批准与复核。
7. **事实边界**：交易集、Agent 调查输出与付款执行器是确定性模拟；不接入真实 ERP、银行通道或在线大模型，页面显示 `simulation` 运行模式。

## 后果

- 迁移到新领域只需替换三层：`domainpack`（证据类型、控制规则、动作白名单、复核断言）、Agent 调查实现和 CyberGuard adapter。
- 演示可如实陈述容器、HTTP、哈希链、审批绑定与回滚失效语义为真实运行，同时明确模拟边界，避免夸大为在线大模型或真实银行系统。
- `agentteams/workers.yaml` 与技能文件描述了把确定性 Agent 替换为受工具权限约束的 AgentTeams Worker 的部署草稿；在真实部署并留存回执之前，不得标记 live run。
- 默认 GHCR 镜像为私有时需要登录或改公开；源码等价验证（同提交本地构建）已完成，见 `docs/CYBERGUARD_RUNTIME_REUSE.md`。
