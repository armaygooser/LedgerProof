# LedgerProof 演示手册

## 演示前检查

```bash
docker compose ps
python scripts/smoke_http.py
```

三个容器应为运行状态，冒烟测试最后输出 `phase: rolled_back` 和 `audit_records: 7`。随后在页面点击“重置演示案件”。

## 90 秒讲解路线

### 0–15 秒：业务问题

“这是一个包含 1,024 笔付款的季度审计项目。传统方式需要多人逐笔抽样；LedgerProof 让七个权限隔离 Agent 做全量调查，人只负责关键决策。”

点击 **一键审计至审批**。

### 15–35 秒：七 Agent 与证据

“系统发现三笔各 ¥98,000 的拆分付款，累计 ¥294,000。证据保全、账目勾稽、异常检测、关系穿透和内控检查分别出具带 Evidence ID 与哈希的结论，规划 Agent 只形成提案，不能自行批准。”

指向风险散点、控制点和 Agent 工作区。

### 35–50 秒：人工审批

点击 **人工批准止付**，展示提案哈希，再确认。

“审批人看到的是影响范围、金额、证据覆盖和完整提案哈希。批准只对这个哈希有效，提案被改动后原批准不能复用。”

### 50–65 秒：受控执行

点击 **执行受控止付**。

“CyberGuard 再次检查权限、批准有效期和提案绑定，只暂停三笔高风险交易，其余 1,021 笔保持释放。”

### 65–78 秒：独立复核

点击 **启动独立复核**。

“第七个 Agent 不相信执行结果的自报，重新读取付款状态，核对范围、金额、证据根和整条 HMAC 审计链。”

### 78–90 秒：回滚

点击 **发起受控回滚**，填写理由并确认。

“回滚释放止付，但不会删除历史；旧 VERIFIED 结论立即失效，提案、批准、执行、复核和回滚仍在哈希链中。”

## 录屏建议

- 画面使用 1920×1080，浏览器缩放 80%–90%。
- 首屏停留 2 秒，随后按上述路径操作。
- 在审批弹窗停留 2 秒，让评委看清提案哈希。
- 最后向下滚动到“哈希证据链”，展示 7 条记录和当前链头。
- 如果需要从 AgentTeams Element 进入，先发送 `agentteams/room-message.md`，再点击发布后的 LedgerProof 链接。

## 故障恢复

```bash
docker compose restart
docker compose logs --tail 100 cyberguard-governance ledgerproof-api ledgerproof-web
```

页面状态不适合演示时，点击 **重置演示案件**。审计账本不会清空，因此全局记录数会持续增加，这是预期行为。
